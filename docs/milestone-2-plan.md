# Milestone 2：视频理解与语义检索开发计划

**状态：计划中，未实现 M2；2026-10-09。** 本文是 M2 的实施与验收入口。M1 实际能力以[验收记录](milestone-1-acceptance.md)为准；本文的质量、成本、性能门槛均为待验证目标，不是实测结论。

## 1. 目标、已有基础与交付边界

用户在项目中上传素材，媒体校验完成后主动分析，再用中文自然语言检索“说到某个观点”或“画面出现某种对象/场景”的片段。结果带素材、来源时间范围和证据，可播放定位，并显式加入当前手动编辑草稿，继续走 M1 保存、预览、确认与导出流程。

M1 可复用身份/项目权限、Cookie + CSRF、Silo 私有对象与短期签名、媒体校验、原始素材不可变版本、代理播放、严格毫秒 DSL、不可变 Revision、审批、独立渲染 Worker 和故障/恢复脚本。当前 Java `assets.analysis_status` 仅为 `NOT_STARTED` 占位；Python 工程、语义任务、pgvector、分析结果和搜索均未实现。

不改变 MP4/MOV、H.264、可选 AAC 等 M1 支持范围，不把语义分析失败写成媒体损坏。M1 `MEDIA_READY` 仅代表可编辑/渲染；分析状态另行维护。真实 4 GB / 120 分钟素材测试继续不执行，用小素材、缩小限额及边界测试验证逻辑；生产容量仍待后续验证。

| M2 必须交付 | 留到后续阶段 |
|---|---|
| Python FastAPI 内部分析/检索 API、独立分析 Worker、持久任务 | M3 LangGraph、Agent 自主规划、Tool Registry/Gateway |
| 中文 ASR、句级时间对齐、场景切分、关键帧、基础 VLM 描述 | 强制词级对齐、说话人身份识别、逐帧动作定位、完整事件/章节树 |
| 项目内中文文本与向量融合检索、证据与粗细时间范围 | 跨项目搜索、独立向量数据库、训练自有模型 |
| 费用估算/预算控制、取消/重试/重建、刷新恢复 | M4 RabbitMQ、完整 Outbox/Inbox、SSE、Agent Checkpoint |
| 分析与搜索 UI、定位播放、显式加入手动草稿 | M5 对话 Patch、自动改写/保存/审批/导出；M6 编辑审美与叙事 |

## 2. 已厘清的需求与实现决策

| 原歧义 | 本阶段决定 | 验收含义 |
|---|---|---|
| 什么素材优先 | 用户确认：中文口播为主，同时验收基本视觉检索 | 转写检索与视觉检索分组评测，不以口播通过代替视觉通过 |
| 本地还是云模型 | 用户确认：云 API 优先，仅用允许外传的测试素材 | 不要求 GPU；本地模型是后续适配备选 |
| 模型是否已指定 | 用户未指定；先资格核验候选，再按价格/质量锁定配置 | 候选名称不代表已购买、已接入或已验证 |
| 上传后是否自动花钱 | 用户确认：用户点击“开始分析”，展示估算后启动 | 上传/媒体校验完成不自动调用收费模型；确认后流水线自动执行 |
| 费用上限 | 用户确认：单素材分析 ¥5，首轮真实模型验收累计 ¥50，均可配置 | 超限拒绝启动或停止派发新请求；不承诺所有时长都能在 ¥5 内完成 |
| 是否引入 Redis | M2 不引入 | PG 任务、租约、费用账本和有限进程缓存足够；以后有测量依据再评估 |
| 是否提前引入 RabbitMQ | M2 使用持久化任务 + 短 HTTP 交接；M4 替换传输适配器 | 不把长视频处理塞进同步 HTTP，不使用内存队列保证可靠性 |
| M2 与 M3 的 Python 边界 | 提前建立 FastAPI 与分析 Worker；M3 增加 Agent 能力 | “独立 Agent Service”不应阻止 M2 建立分析工程 |
| 检索范围 | 默认当前项目全部已发布索引，可筛选素材及语音/视觉/混合 | Java 校验所有素材归属；指定范围没有索引时解释状态，不静默扩大范围 |
| 基本视觉检索是什么 | 持续可见的对象、场景、画面文字线索；返回采样证据覆盖窗口 | 不保证快速短动作、遮挡对象、人物身份或帧级动作边界 |
| 搜不到如何处理 | 返回空结果和未分析/模态缺失等原因 | 不强行返回最高分并伪称匹配；阈值在开发集校准后冻结 |
| 结果怎样进入剪辑 | 用户显式加入当前草稿，再按 M1 全量保存新 Revision | 不覆盖已有草稿，不绕过乐观锁与审批 |

根设计要求最终长任务使用 RabbitMQ，但里程碑将 MQ 放在 M4；这是明确的分阶段取舍。M2 的请求表承担可靠交接职责；M4 保留 request_id、幂等键、代次和任务状态语义，仅替换提交/状态传输，不重写分析计算。若以后要求 M2 即接入 MQ，需要更新范围与验收，不静默扩大本计划。

## 3. 技术与模型资格门槛

### 3.1 工程选型

Python 3.12 + uv/锁文件、FastAPI/Pydantic、psycopg、Alembic、httpx、S3 协议客户端，Ruff、mypy、pytest。初始化时选兼容的精确版本并生成锁文件，测试后固定镜像 digest；本计划不虚构尚不存在的运行命令。M2 不安装 LangGraph、RabbitMQ 或 Redis。

Java 保持 JDK 21 / Spring Boot 4.1.1 / Maven wrapper 3.9.11；前端保持 Node 24.21.0 / pnpm 11.24.0 与现有 Vue 工程。Python 分析容器复用 M1 验收的 FFmpeg 6.1.1-3ubuntu5，增加 PySceneDetect/OpenCV 兼容版本；不能用宿主 FFmpeg 8.x 测试代替容器结果。

PG 保持现有 17.6 pinned base，构建含 pgvector 的镜像并固定扩展版本/校验来源，同时启用中文文本候选所需的 pg_trgm；不换主版本或删除卷。Silo 保持现有固定版本和 S3 接口。运行角色与迁移角色分开；扩展安装由基础设施初始化角色完成。

### 3.2 模型候选与锁定流程

候选核查与官方依据见[模型选型研究](m2-model-research.md)。首轮考察同一区域的 `paraformer-realtime-v2`、`qwen3-vl-flash-2026-01-22` 和 `text-embedding-v4`，减少多个账号的初次接入成本；另以相同小样本比较一个新版 ASR 候选，先核查时间戳能力。研究记录了北京地域公开价格及 VLM 别名/快照输出能力差异；这些是候选方向，模型/区域/价格必须经过账号与小样本资格核验，不将它们当成已验证依赖。

阶段 P0 记录：供应商与区域、精确模型标识/可获得的版本、中文支持、句级时间戳、请求限制、数据保留/训练使用政策、价格及计费单位/币种/日期、速率配额、错误/超时/取消语义、返回 usage 和 request_id 的能力。Embedding 初始以单一模型 1024 维为目标，验证支持后固定；若不支持则在创建迁移前更新本计划与契约。

ASR 必须能接收受控音频块并返回句级时间，不依赖云端访问本机 `localhost` 签名 URL。优先考察直接音频上传/流式传输适配器；文件 ASR 如只支持公网 URL，则不作为默认实现。若最终必须使用文件 URL，需要另行明确云端私有暂存、短期签名、费用、删除 TTL 和外传范围，不能直接公开本地 Silo 或设置公共 bucket。

VLM 使用本地提取的少量压缩图片直接上传，限制图片数、尺寸和 payload；不直接把完整视频交给模型。Embedding 只传转写/描述文本。没有音轨或没有有效语音可以跳过 ASR；不拿空音频反复付费重试。云模型输出结构必须本地校验，文本不能驱动任意 URL 获取、Shell 或业务工具。

P0 用允许外传的小型开发集做资格试验；记录使用量及账单，达到 ¥50 累计门槛停止新的付费请求。账号/密钥未准备时继续 mock 工程与流水线验证，将真实模型验收标为未执行；不能用 mock 结果宣称 ASR 或检索质量通过。

## 4. 完整用户链路与接口

1. 上传并达到 `MEDIA_READY`；显示“未分析”，手动剪辑仍可使用。
2. 点击“开始分析”，Java 返回预检估算：模型/区域、音频分钟、采样帧/预计文本量、价格版本、预计金额及上限、外传内容、可能超限。价格未知时禁止启动收费分析。
3. 用户确认估算，提交 estimate_id 与 Idempotency-Key；Java 在事务中重新校验权限、素材版本、有效期和预算，创建任务。过期/模型或策略变化返回冲突并重新估算。
4. UI 轮询阶段、已完成数量、费用、缺失模态、错误/可重试性；刷新恢复，隐藏页停止轮询，复用现有退避策略。
5. 输入中文描述、范围与模态，返回可验证的片段证据；点击定位播放，显式加入草稿后走 M1 保存/渲染。

以下为**计划新增契约，当前不可调用**；P0 将请求/响应、错误码、限额和夹具写入共享 OpenAPI/JSON Schema，Java、Python、Vue 消费同一契约，不照抄旧预研路径当成已实现接口。

| 方向 | 建议接口 | 必要语义 |
|---|---|---|
| Vue → Java | `POST /api/v1/assets/{id}/analysis/estimate` | 只做本地估算，不调用收费模型 |
| Vue → Java | `POST /api/v1/assets/{id}/analysis` | 确认估算、幂等启动，202 + analysis_id |
| Vue → Java | `GET /api/v1/assets/{id}/analysis` | 最新尝试与可用旧索引分开，状态/阶段/费用/模态/错误 |
| Vue → Java | `POST /api/v1/assets/{id}/analysis/cancel`、`.../retry` | 取消与补跑须保持预算和代次约束；重建通过显式分析请求表达 |
| Vue → Java | `POST /api/v1/projects/{id}/segments/search` | query、asset_ids、modality、top_k；返回结果与覆盖信息 |
| Java → Python | `POST /internal/v1/analysis-runs` | 幂等落库后立即 202；不能等待模型处理 |
| Java → Python | `GET /internal/v1/analysis-runs/{id}`、`POST .../{id}/cancel` | 状态与版本摘要；幂等取消 |
| Java → Python | `POST /internal/v1/segments/search` | Java 提供受权素材及已发布 analysis_id 集合 |
| Java → Python | `POST /internal/v1/assets/{id}/revoke` | 持久化代次墓碑、取消/清理，重复可安全执行 |
| Python → Java | `POST /internal/v1/analysis-invocations/reserve`、`.../{id}/settle` | 以 invocation_id 幂等预留/结算；Java 账本是预算权威 |
| Python → Java | 内部任务授权/续租及素材读取授权端点 | 绑定任务、asset_version、generation；短期可刷新来源访问 |

所有公网接口继续 Cookie/CSRF/owner 校验；内部服务单独认证、最小权限、仅内部网络可达，生产要求 TLS。Java 不全局关闭 CSRF；浏览器不直接调用 Python，不持有模型密钥。内部凭证、signed URL、原始 provider 日志不进入 API 响应/日志/提交。内部读取不接受任意 URL，限制路径和 provider 结果域名，防 SSRF。

搜索结果至少含 asset_id/version、analysis_id、segment_id、start_ms/end_ms、modality、语音摘录/视觉描述、frame_id 与原始采样时间、排名及 matched_by。分数是排序值，不展示成“正确概率”；视觉窗口显示“采样定位”，语音显示句级来源。取证图片通过 Java 授权短期签名，不暴露永久对象路径。

初始 API 限额建议：query 最多 500 字符、top_k 默认 10/最大 20、单次最多 50 个素材；结果确定排序并去重，不在 M2 增加复杂游标分页。未就绪返回明确原因；Python/Embedding 服务不可用返回可恢复错误，不伪装为“没有匹配”。响应返回查询时索引快照，UI 丢弃过期请求响应，Java 返回前再次过滤已撤销素材。

## 5. 任务、幂等、状态与数据生命周期

### 5.1 可靠交接

Java 同一事务写业务分析请求及素材额度预留；调用预留从该额度分配，不再次扣两份预算，背景 dispatcher 按持久状态重试短提交；Python 只在任务可靠入库后返回 202，request_id 为唯一键，payload_hash 用于一致性校验。同键同负载返回原任务，同键异负载冲突。API 不通过 FastAPI BackgroundTasks 或进程队列承担可靠任务。

独立 Python Worker 从 `agent_schema` 抢占任务，短事务 `FOR UPDATE SKIP LOCKED`，初始并发 1、租约 30 秒/心跳 10 秒，可配置。每次领任务生成 attempt_token；阶段提交必须满足当前 token、generation 和取消条件。Java 定期查询任务摘要，服务重启后继续补投递/对账；提交响应丢失、重复请求、双 Worker 和网络中断均不新增同一逻辑任务。

跨服务没有“恰好一次模型计费”的保证。每个模型调用在发送前记录独立 invocation_id、输入 hash 和预算预留，收到供应商受理响应后尽快持久化 provider request/task_id，再记录最终响应与 usage。可安全重试的 429/明确未受理错误指数退避（初始最多 3 次，遵守 Retry-After）；有 provider task_id 时查询原任务。已发送后超时且不能查明是否计费，进入 `NEEDS_REVIEW`，保留预留并停止自动重发，用户可在新估算下决定下一次尝试。

### 5.2 状态与版本

| 对外 analysis_status | 意义 |
|---|---|
| `NOT_STARTED` | 从未请求分析 |
| `QUEUED` / `RUNNING` / `CANCEL_REQUESTED` | 已持久受理 / 正在执行 / 正在停止 |
| `READY` | 所需模态完成并发布；无音轨时 ASR=SKIPPED 合法 |
| `PARTIAL_READY` | 仅部分模态可检索，缺失模态与原因明确 |
| `FAILED` / `CANCELLED` / `BUDGET_EXCEEDED` / `NEEDS_REVIEW` | 终止或待查明，不代表 MEDIA_INVALID |

ASR、scene/frame、VLM、Embedding 每阶段保存状态及产物；无有效语音是 SKIPPED，不是 ASR_FAILED。只有 VLM 描述成功但向量失败时，可发布明确标记的文本检索能力；搜索响应列明支持的检索方式，不能按完整语义检索通过；缺模态不能按完整 READY 验收。阶段名用于进度，未完成数量不伪造百分比。

分析以不可变 analysis_id + asset_version + content_hash + pipeline_fingerprint（模型、维度、提示词、采样/分块策略、实现版本）保存。失败补跑可复用同指纹成功产物；改变模型/策略新建版本，不能混用不同 Embedding 空间。准备完成后 Python 标记 PREPARED；Java 校验当前任务与素材代次，事务更新权威 active_analysis_id，再允许搜索该版本。Python 搜索仅使用 Java 传入的已发布版本集，不自行切换业务可见版本。

重建期间旧已发布索引继续可用，接口同时展示最新尝试状态与 searchable_analysis_id；重建失败不清空旧结果。旧索引 GC 必须等待 Java 撤销/无活动引用。搜索命中是原始素材时间段，不以分析版本改变 M1 保存的剪辑方案。

### 5.3 取消、删除与费用控制

取消在 Java 事务中提高控制代次并持久记录，再可靠交接；Worker 在阶段边界、下载、模型请求前及结果提交时检查，停止本地子进程，尝试取消供应商任务。无法撤回已发请求时明确可能仍计费；过期 Worker 不能回写可见结果。

删除保持 M1 已保存 Revision 引用禁止删除、媒体任务冲突检查。增加语义任务与读取租约检查：活动分析先取消，尚未确认停止且租约有效时 DELETE 返回 409 `ANALYSIS_BUSY`，UI 提供取消后重试。可删除时 Java 同事务设 DELETING、撤销 active_analysis_id、提高 generation、持久排入 revoke/清理请求，先隐藏素材与索引。

Python revoke 先落代次墓碑再清理，阻止迟到 submit/publish；Worker 开始与发布前也向 Java 检查授权。Java 等撤销确认及读取租约终止/过期加安全宽限后清理源/代理；Python 派生表与对象清理用可重试清单追踪。Java 只在双方必要清理完成后标 DELETED，整个删除仍为 202 异步契约。服务离线时停在 DELETING 可恢复，不能为了完成状态漏清索引，不能删除其他素材产物。

预算与费用权威账本归 Java；Python 调用内部 reserve/settle API，以 invocation_id 幂等记录预留/结算，不能直写业务账本。Java 不可用时暂停新收费调用；已完成响应先持久保存在 Python，再重试结算，对账不重复收费。费用用整数微元/明确币种账本，不用浮点。每个收费调用前以 PG 原子预留；计入音频、图片/文本输入输出、Embedding、可能的重试及暂存/网络费用。每个阶段及调用关联 request_id/analysis_id/invocation_id/trace_id，记录耗时、用量、重试和稳定错误码；不记录原文、签名 URL 或密钥，调试正文只进入受控忽略目录。价格表与估算策略版本固定，预留保守上界与余量；供应商没有可计算上界的调用不得以“预估很低”突破预算。达到单素材/运行累计预算不再发起请求，不保证供应商最终账单能被事后撤销。

¥50 作为首轮真实验收的持久 run 预算，服务重启或多个素材并发不能重置。生产分析预算另行配置；查询 Embedding 也计费，初始项目查询日预算建议 ¥1、每用户每分钟最多 20 次请求，可配置并在资格核验时检查定价；采用有界缓存，缓存键包含项目/授权范围、模型指纹及规范化查询，不能默认无限。重复点击和同一请求重试共享账本；重新分析展示已花费与本次剩余额度，不能用换 analysis_id 绕过单素材累计门槛。

## 6. 分析流水线与统一时间轴

1. **授权与准备：** 读取 Java 提供的版本/hash/时长/旋转/audio_start/video_start，下载任务授权范围内的原始素材并核验 hash；复用 M1 探测结果，不改变媒体资格。内存/磁盘不足、签名过期、源不存在为可区分错误。
2. **音频：** 提取 mono 16 kHz PCM，按供应商限制切成初始 60 秒块、1 秒重叠，可配置；记录音频来源起点，不混淆补静音、裁切及重采样偏移。ASR 句级输出映射回来源时间，重叠文本/句去重，跨块句保留合并证据。首版不强制 WhisperX 词级对齐。
3. **画面：** PySceneDetect 检测镜头变化，结合固定上限窗口切分长静态镜头；只把 scene 当视觉采样依据，不能声称完整语义事件边界。初始每 10 秒窗口采 2 帧，镜头边界补帧；每窗口最多 3 帧、每素材最多 120 帧、长边不超过 768 像素，阈值/预算可配置。超限在估算时提示覆盖变稀；低覆盖不能按完整视觉验收通过。
4. **VLM：** 每窗口有界多图请求，传 frame_id 和系统记录的来源时刻，输出中文描述/可见对象/文字线索及引用 frame_id。只接受实际帧 ID；时间由系统映射，忽略/拒绝模型自编时间。看不清输出 unknown，不补造身份/动作。
5. **片段：** 转写按句聚合成初始 5–30 秒文本片段，单长句允许例外但不截断来源；视觉按有证据的采样窗口形成片段。不把整段摘要当唯一索引，不强行令场景、话题、事件严格树形包含。
6. **索引准备：** 音频/视觉分别形成文本、Embedding、证据和覆盖范围；校验所有引用与边界后进入 PREPARED，并由 Java 发布。

统一时间为 **M1 归一化原始视频播放轴**，单位整数 ms，区间 `[start_ms,end_ms)`；合法范围 `0 <= start < end <= duration_ms`。音频识别时间需加 audio_start − video_start 与 chunk 起点，并校正裁切/补静音；负起点与超末尾显式裁剪，空区间丢弃并记原因。画面按实际解码帧 PTS 映射，不能用 frame_index/fps 替代 VFR 时间；旋转后取证，代理只供播放，不成为另一条检索时间轴。

视觉结果返回证据点与覆盖窗口，不因抽样宣称精确动作始末。与 M1 DSL 集成只使用校验过的来源范围；渲染的帧量化仍归 Java Compiler，检索不改写 DSL 时间语义。旋转、VFR、非零 PTS、音频领先/滞后、无音轨、短音轨及跨块重叠必须有小型回归素材。

## 7. 存储、隔离与检索实现

### 7.1 所有权与迁移

实际 M1 表以现有 Flyway 为准，不能为匹配预研 `business_schema` 示意图搬迁现有表。Java 新增 analysis_requests、预算/调用预留摘要、asset 分析控制代次与 active_analysis_id；Python 只写 `agent_schema` 的 analysis_runs/stages、transcript_segments、visual_segments、frames、embeddings、provider_invocations、cleanup/revocation。Java 通过 API 获取派生结果，Python 通过内部 API 获取业务授权；运行角色不能跨 Schema 写入或直读对方业务表。

跨 Schema 用 UUID + version/generation 和受控 API 关联，不建立要求 Python 拥有 Java 表权限的外键。project_id 是 Java 传入的授权快照，不能接受浏览器自行声明的 owner。证据与中间对象位于专用私有 analysis 前缀/桶，Python 最小权限身份只读被授权源、读写分析产物，不使用 Silo 管理员凭证。

向量初始 `vector(1024)`，单一固定 Embedding 模型，每条包含 analysis_id、project_id、asset_id/version、modality、segment_id、模型指纹；唯一约束防重复。新增模型维度使用新表/分区或新版本迁移，不将不同空间写到同一检索集合。

PG 扩展先在隔离卷升级已有 M1 数据副本，再验证 Flyway/Alembic、角色负面权限、旧 M1 可读写、dump/restore 含 vector、重建索引。数据库回退通过迁移前备份恢复到独立库并切换验证；不默认 DROP 已有表或删除卷。派生向量可重建不等于费用/任务/撤销账本可丢弃。

### 7.2 中文与多模态检索

按授权项目/素材/active_analysis_id **先限制集合再排名**，初始 pgvector 精确 cosine 搜索，使用 B-tree 索引辅助范围；不一开始加 HNSW。项目 10,000 片段作为初始性能测量规模，超过实际目标后再依据 profiling 评估 ANN，过滤后召回下降必须单独验证。

中文文本支路使用明确的规范化（Unicode NFKC、空白/标点策略）与字符子串/pg_trgm 候选；pg_trgm 覆盖不了的短词需有显式子串路径。保留原文供展示。默认 PostgreSQL 英文 tsvector 不能当成中文分词方案；如果引入中文 tokenizer，必须补词典/版本与契约回归。

查询仅生成一次当前模型 Embedding，分别取语音和视觉候选，与中文文本候选做 RRF 融合；常量、候选数和阈值在开发集调参后冻结。模态筛选明确：语音模式只返回转写证据，视觉模式只返回图片证据，混合模式可返回两者并标注。按素材/模态的时间重叠去重，保留最有用证据，跨镜头不过度拼接长区间。

无匹配阈值不能直接使用 RRF 排名分数当置信度：先对原始向量相似度、词面命中、模态质量/覆盖做资格过滤，再融合排序；用负例校准。返回 coverage（已索引/未分析/失败/稀疏），解释信息不足。取消、重建、删除与搜索并发时，Java 校验已发布版本快照并在响应前移除撤销素材，过时结果加入草稿时再次检查可用性。

## 9. 验证策略与量化验收

### 9.1 当前可执行命令与后续入口

本次纯文档交付在仓库根目录执行：

```bash
python3 scripts/verify-docs.py
git diff --check
```

实施中 Java 工作目录 `backend/` 执行 `./mvnw -B -ntp verify`；前端工作目录 `frontend/` 执行 `pnpm format:check`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。真实集成测试需实际启用且统计跳过数；现有 `scripts/test-m1.sh`、`scripts/test-media.sh` 与恢复入口见[验证脚本](../scripts/README.md)。Python 的锁定安装、Ruff/mypy/pytest/构建/迁移、M2 脚本命令在 P1/P7 建立配置后写入 README，现阶段没有这些可运行入口。

CI 默认使用本地 mock provider 验证受控响应、usage、429/5xx/断流/超时/坏 JSON，不外传或扣费。真实 PG/Silo/FFmpeg/Python HTTP 的集成与浏览器冒烟使用隔离项目和小素材；收费模型质量评测单独手动启动，日志/素材/凭证留忽略目录，不作为每次 PR 的自动要求。

### 9.2 功能、可靠性与安全

- 不同用户、不同项目、伪造 asset_id/version/analysis_id、internal 凭证缺失/错误、签名过期、越权证据读取：无数据泄漏，内部路由无法通过用户 Cookie 冒充；Python DB 角色无业务表访问权。
- 同估算重复确认/多标签页/并发预算预留，不产生重复逻辑任务；dispatcher 丢响应、API/worker kill、PG/Silo/provider 中断后恢复；旧 attempt_token/代次结果不能发布。
- 取消前后调用费用、已付费超时未决、预算耗尽、价格改变、estimate 过期，均有可见结果和可追踪账本；不会盲目自动补发。
- 删除与下载/任务提交/索引发布/搜索/重建同时发生，延迟 revoke 重启仍执行；无索引复活、无别的素材被清理；Revision 引用删除约束及删除 202 保留。
- 有音轨但无语音、无音轨、短音轨、跨块重复、旋转/VFR/非零 PTS、稀疏采样、未知画面、模型幻觉/错误结构、单模态失败、旧索引可用、空检索均覆盖。
- M1 上传→手动方案→保存→PREVIEW→确认→FINAL 的真实浏览器回归；检索加入草稿不隐式覆盖其他修改，409 并发冲突保持原行为。

### 9.3 真实模型质量与时间定位

在 P0 准备可外传、自制/授权的小型素材，建议 12–16 段、总时长 20–30 分钟，覆盖中文清晰口播、少量背景噪声、中英混合词、静音、有字画面、持续可见对象/室内外场景。开发集与冻结验收集按素材分离；合成颜色画面仅验证工程，不能充当自然视觉能力验收。

冻结验收集至少包含 20 条语音正例、10 条视觉正例、10 条无匹配负例，人工标注来源区间、证据模态与可接受候选，不凭模型自身评分判断。瞬时动作不在基本视觉正例集内；视觉正例目标至少持续 10 秒，人工标注先于取帧策略冻结；若未取到证据仍算该正例检索失败，不能事后剔除。短事件作为额外能力边界组单独报告，不并入“视频确实没有该内容”的无匹配负例统计。

| 指标 | 初始通过目标（待实测） | 计算方法/限制 |
|---|---|---|
| 中文 ASR | 清晰口播 CER ≤15%；噪声组单独报告 | 人工转写去标点/空白并固定规范化；不挑选最好的句子 |
| 句级时间 | 清晰口播人工句边界绝对误差 P95 ≤1000 ms | 与来源视频人工标注比较，不只检查合法范围 |
| 语音检索 | Hit@5 ≥85% | 命中须素材/模态正确，至少一个 top5 区间与标注 temporal IoU ≥0.5 |
| 视觉检索 | Hit@5 ≥70% | 素材正确、取证帧可证目标、窗口与标注有交集；另报窗口长度/IoU，不伪称精确始末 |
| 无匹配 | ≥90% 负例返回空结果 | 开发集冻结资格阈值；服务故障不算正确空结果 |
| 边界/权限 | 全部合法区间、0 越权、0 过期版本发布 | 确定性断言，不以平均质量抵消错误 |
| 费用 | 单素材累计 ≤¥5、首轮真实验收累计 ≤¥50 | 包括资格实验/验收中的查询Embedding与重试；账单未知按未决预留计入 |

同时记录 Hit@1、模态覆盖、失败率、每素材费用、真实/估算偏差和分组样本量。样本较少，指标不代表全领域泛化；不通过时先定位 ASR/采样/描述/Embedding/融合哪步失效，更新计划后重评，不能降低断言掩盖问题或只删除困难样本。

### 9.4 性能、资源与恢复

初始分析并发 1，分析 Worker 2 CPU/2 GiB 为测量起点、独立 scratch 卷及有界磁盘预留，沿用 Java 的低成本资源观测思路；OOM 或解码压力出现时用证据调整，不占用 Render Worker 执行池。每个子进程有超时、取消、有限 stderr 和输出上限；临时对象按任务归属与租约/TTL 清理。

隔离 PG 中建立一个项目 10,000 片段和多个干扰项目，以固定查询集合测服务内搜索 P95 ≤500 ms（不含云 Query Embedding）；端到端初始 P95 ≤3 s，记录缓存命中、云耗时、环境与并发，超标时分类定位。10 分钟口播分析以 ≤10 分钟为初始观察目标，供应商排队/额度另报；先报告实测再决定是否作为硬性 SLO。

恢复测试包括已有 M1 DB 的扩展升级、vector dump/restore、任务/预算/撤销账本持久恢复、Silo 派生对象清单一致性。用新临时库/卷验证，不破坏原测试数据；只宣称验证过的恢复路径。
